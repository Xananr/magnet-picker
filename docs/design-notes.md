# 磁力筛选器（MagnetPicker）— 关键信息

**位置**：`/Applications/磁力筛选器.app`（已 ad-hoc 签名、已去隔离属性，双击即用）

原生 SwiftUI App（部署目标 macOS 13，无第三方依赖，不依赖 Python）。工程源码、构建目录、测试产物已按要求清理，此文件为唯一留档。

## 它做什么

粘贴一批 magnet / ed2k 链接（或整页 HTML），先探测每条链接的**真实做种数**，再按**片源质量**打分排序，挑出最值得下的线路；支持分段（按片名 / 按分辨率）与批量复制。

## 界面

- 顶栏：共 N 条 / 有做种 N、参数面板、清空、开始探测（探测中变停止 + 进度）
- 输入区（最轻）：粘贴框 58pt，可展开；右侧网址栏 + 「抓取」；导入文件 / 读剪贴板
- 筛选栏（单行）：搜片名、分辨率（全部/4K/1080p/720p）、分组（片名/分辨率/不分段）、去枪版、做种≥N、复制菜单、导出菜单
- 结果区（主体）：`# 分数 做种 分辨率 来源 体积 版本`，按综合分降序；点行右侧滑出详情（片源标签、综合/可用性/质量/做种、每条 tracker 通断）
- 状态栏：进度条、状态文案、耗时、显示数、收起详情

## 探测与评分口径（都是实测校准过的）

- 做种数优先 **scrape（BEP 48，只读）**；不支持才退回 announce（`numwant=0`，不占 peer 名额）；HTTP 超时后不再补 announce，避免耗时翻倍
- 多条 tracker 取**最大值**，不做求和（同一 swarm 会被重复计数）
- 无 tracker 数据时才用 **DHT get_peers** 兜底（单线程 + 非阻塞 socket）
- 体积优先取 magnet 的 `xl`，缺失时从网页锚文本（如 `4K 15.29GB<strong>文件名</strong>`）补
- 可用性 = `min(1, log10(1+做种)/log10(51)) * 100`；综合分 = 可用性 × 权重(默认 0.6) 与质量分加权
- 枪版 CAM/TS 质量 -30 且总分乘 0.35；3D Half-SBS -8；合集/剧集 -4；体积偏离该分辨率常见区间扣分
- 解析完立即算出分辨率/来源/音轨，表格在探测前就有信息可看
- ed2k 只解析与参与评分，源数标「未知」、不参与排序（服务器网络已基本废弃，真实源数要 Kad，拿不到）

## 运行参数与实测

- 默认：tracker 超时 5s、DHT 7s、每条最多 10 个 tracker、并发 16、启用公共 tracker、可用性权重 0.6、缓存 6h
- 缓存：`~/Library/Caches/MagnetPicker/probe-cache.json`（删掉即强制重新探测）
- 实测：49 条种子 ≈ 490 次请求，约 70s 出全量；命中缓存 0s
- 占用：包 3.7 MB、release 二进制 1.7 MB；探测完空闲常驻约 100 MB、CPU 0%
- 自检（不弹窗）：`/Applications/磁力筛选器.app/Contents/MacOS/MagnetPicker --selftest`

## 调试启动参数

`--load-url <网页地址>` 启动即抓页面、`--load <txt/html 路径>` 导入文件、`--autoprobe` 自动开始探测、`--select` 自动选中首行（截图核对用）。

## 已知边界

- 本机走代理（TUN fake-ip）时 UDP 到公网 DHT 基本不通，只有 `dht.transmissionbt.com` 能连；DHT 仅作兜底，做种数以 tracker 为准
- PT 私有站需要 passkey，公网探不到，会显示 0 做种（正常）
- 探测纯只读：不加入任何下载队列、不改动任何种子文件

## 曾经验证过的样例（xbgame.net/951.html，《奇异博士2》）

49 个唯一种子、37 个有做种；最优 `2160p WEB-DL DDP5.1 Atmos HDR H.265-EVO 22GB`（66 做种，93.5 分），次优 `2160p BluRay REMUX HEVC DTS-HD 56.3GB`（39 做种，93.5 分），1080p WEBRip 9.3GB 61 做种 86.7 分。
